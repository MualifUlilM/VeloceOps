Database-Enforced Multi-Tenant Isolation

VeloceOps strictly avoids vulnerable frontend-only filtering. All database queries execute against PostgreSQL 16 Row-Level Security policies. Even if a bad actor modifies the client query, PostgreSQL automatically guarantees zero cross-tenant data leakage.

Active Production Policy (`supabase/migrations/20261024000001_core_schema.sql`)
-- 1. Helper function to extract tenant_id from cryptographically verified JWT
CREATE OR REPLACE FUNCTION public.current_tenant_id()
RETURNS UUID AS $$
BEGIN
    RETURN (auth.jwt() ->> 'tenant_id')::uuid;
END;
$$ LANGUAGE plpgsql STABLE SECURITY DEFINER;

-- 2. Strict read isolation policy on invoices
ALTER TABLE public.invoices ENABLE ROW LEVEL SECURITY;

CREATE POLICY "tenant_isolation_invoices_select"
ON public.invoices FOR SELECT
USING (tenant_id = public.current_tenant_id());

-- 3. Role-Based Access Control (RBAC) write guard
CREATE POLICY "rbac_invoices_write"
ON public.invoices FOR INSERT
WITH CHECK (
    tenant_id = public.current_tenant_id()
    AND (auth.jwt() ->> 'app_role') IN ('OWNER', 'FINANCE')
);
